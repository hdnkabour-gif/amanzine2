# AMANZINE — طبقة الذكاء (Hybrid Understanding) — قرارٌ معماريّ

> السؤال: هل نربط AMANZINE بذكاءٍ (Gemini/ChatGPT/Claude) بدل كتابة ملايين كلمات Arabizi؟
> **الجواب الصادق: نعم — ضرورةٌ لا رفاهيّة. لكن بشرطٍ واحدٍ حاسم: الذكاء يَفهم، وAMANZINE يقرّر.**

---

## ١) لماذا القواعد وحدها تفشل (أنت محقّ)
لا تنتهي: `bghit / bghet / bghite / b8it` · `casa / casablanca / dar lbayda` · خلط
`bghit plombier f casa` · `kanbi3 laptops` · فرنسيّة · إنجليزيّة. **لا أحد يحلّها بالقواعد** —
لا Google ولا OpenAI. القواعد أرضيّةٌ، لا سقف.

## ٢) لماذا «الذكاء لكلّ شيء» يفشل أيضًا (الخطأ المقابل)
لو تركنا Gemini يقود، يصير AMANZINE **مجرّد واجهةٍ لـChatGPT**: يردّ بفقراتٍ طويلة
(«يمكنك الذهاب إلى المستشفى…») بدل قرارٍ منظّم. نحن لا نريد نصًّا — نريد **بيانات**:
`{ intent, city, profession, confidence }` ثمّ **AMANZINE** يبني التجربة.

## ٣) الحلّ: ثلاث طبقات (Hybrid)
```
المستخدم → [١] قواعد سريعة → واثقة؟ ─نعم→ قرار AMANZINE
                     │
                     └─لا/صعبة→ [٢] LLM يُرجع JSON → [٣] طبقة AMANZINE تقرّر
```
- **[١] قواعد (فوريّة، مجّانيّة، بلا شبكة):** التحيّات، الحالات الواضحة («بغيت نبيع»، «الما كيقطر»).
  هي بالفعل موجودة: `understand()` + `readHuman()` + `deArabizi()`.
- **[٢] LLM (للصعب فقط ~١٠-٣٠٪):** قصص طويلة · Arabizi خارج القاموس · خلط لغات · غموض.
  **يُرجع JSON فقط** بنفس شكل مخرجاتنا الحاليّة — لا نصًّا للمستخدم.
- **[٣] طبقة AMANZINE (الأهمّ، وهي موجودةٌ اليوم):** `decideInterface()` يحوّل الفهم إلى مسار.
  **الذكاء لا يملك الحوار — AMANZINE يملكه.**

> النقطة الجوهريّة: **الطبقة [٣] مبنيّةٌ أصلًا في الكود.** ربط الذكاء ليس إعادة بناء — بل
> **مصدرُ فهمٍ إضافيّ** يُغذّي `Understanding`/`HumanRead` نفسها. إضافةٌ لا هدم (تحترم الـ Freeze).

## ٤) عقد الإخراج (JSON Contract) — نفس شكلنا الحاليّ
```json
{ "intent": "BUY|SELL|HELP|SELF|QUESTION|EXPLORE|NONE",
  "profession": "سبّاك | null", "problem": "تسرّب ماء | null",
  "city": "الدار البيضاء | null", "object": "منتج | null",
  "language": "darija|ar|fr|en|mixed", "confidence": 0.0 }
```
مثال: `bghit necheri chi haja l walidi` → `{intent:"BUY", object:"منتج", target:"الوالد", confidence:0.98}`.
LLM يفهم، وAMANZINE يسأل السؤال التالي. يُدمَج JSON في `Understanding` كأيّ مصدرٍ آخر.

## ٥) ثلاث حقائق هندسيّة أغفلها التحليل — وهي التي تحسم النجاح/الفشل
1. **الكُمون (Latency):** LLM يضيف ١-٣ ثوانٍ. لو ضربنا الذكاء عند **كلّ حرف** ينكسر إحساس
   «الفهم الفوريّ» في Hero. القاعدة: **القواعد تُجيب فورًا أثناء الكتابة؛ الذكاء يُستدعى فقط
   عند التوقّف/الإرسال للحالات الصعبة**، مع «كنقلّب معاك…» أثناء تفكيره.
2. **الأرضيّة عند انقطاع الشبكة (Offline floor):** شبكات المغرب متقلّبة. **يجب أن تبقى القواعد
   تعمل حين يتعذّر الذكاء** — لا ينهار التطبيق أبدًا. تدهورٌ رشيق: صعبة + لا شبكة = «كمّل معايا» بالقواعد.
3. **مكان المفتاح + الخصوصيّة:** مفتاح الـAPI **على الخادم (Express) لا في المتصفّح** — وإلّا يُسرَق.
   ونُعلم المستخدم أنّ نصّه قد يُعالَج خارجيًّا (شفافيّة).

## ٦) بوّابة التصعيد (Escalation Gate) — للتكلفة
لا نرسل كلّ رسالة. نرسل للذكاء **فقط** حين: (ثقة القواعد منخفضة) **و** (النصّ غير تافه:
طويل/لاتينيّ/مختلط/غامض). التحيّات والحالات الواضحة تبقى قواعد ⇒ الاستخدام ينزل إلى ~١٠-٣٠٪.

## ٧) أيّ نموذج؟
**القدرة على الإخراج المنظّم (JSON mode) أهمّ من العلامة.** Gemini Flash: رخيص + سريع + جيّد
بالدارجة = افتراضٌ معقول للتكلفة. أيّ نموذجٍ قويٍّ يعمل ما دام يلتزم بعقد الـJSON. القرار قابلٌ للتبديل.

## ٨) خطّة تنفيذ منخفضة الخطر (بلا مفتاح، بلا تكلفة — الآن)
يمكن بناء **السقالة كاملةً بلا أيّ مفتاح**: `understandHybrid()` = قواعد أوّلًا + بوّابة تصعيد
+ محوّل مزوّدٍ خلف واجهة (`LLMProvider`) مُنفَّذها اليوم **stub يُرجع null** ⇒ يسقط للقواعد.
يوم تُضيف مفتاحًا = **دالّةٌ واحدة** تُملأ. لا يتغيّر شيءٌ في الواجهة. قابلٌ للاختبار الآن.

> **الخلاصة:** نعم للذكاء — لكنّه **عينٌ تفهم، لا لسانٌ يقرّر**. القواعد للسرعة والأرضيّة،
> الذكاء للصعب، وAMANZINE يبقى صاحب الحوار. هذا هو التوازن الصحيح لمشروعك.

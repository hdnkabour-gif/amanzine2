# 08 — حلقة التعلّم (The Learning Loop)

> ما الذي يجعل AMANZINE مختلفًا عن أي Marketplace؟ ليس البحث — بل أن **كل تفاعل يولّد معرفة تُحسّن القرار القادم**.
> ينفّذ القانون ١١ (اختبار المعرفة). يخضع للرؤية (`00`) والخصوصية (`DR-0003` §7).

---

## المبدأ

المستخدم لا ينفّذ «بحثًا» — إنه يعيش **قصّة**:

```
بحث → نتائج → نقر → فتح صفحة → قراءة تقييمات → اتصال → حجز → دفع → تقييم → عودة → بحث جديد
```

كل سهم في هذه القصّة **إشارة**. مجموع الإشارات = **عقل AMANZINE**. لا نتعلّم من البحث وحده، بل من القمع كاملًا.

> القاعدة (القانون ١١): لا نبني أدوات منفصلة؛ نبني **حلقة واحدة** يغذّيها كل تفاعل.

---

## كيف نبنيها — بالتطوّر فوق Event Bus، لا كمحرّك جديد

العمود الفقري موجود: `Event Bus` + `Activity` ينشران أحداثًا موحّدة عن القمع كلّه:

| الحدث | مرحلة القمع |
|-------|-------------|
| `search.executed` / تنفيذ بحث | Search |
| `business.viewed` · `product.viewed` · `service.viewed` | View |
| `business.clicked` | Click |
| `business.contact` | Contact |
| `booking.created` | Booking |
| `order.created` | Order (proxy الدفع) |
| `review.created` | Review |

**Learning Loop = مشترك واحد** (`learning.js`) على هذا الناقل — من عائلة `analytics`/`rules` نفسها (القانون ٤: نعيد استخدام الناقل، لا ننشئ طبقة جديدة). يحوّل الأحداث إلى **تجميع يومي مجهّل** (`learning_daily`).

---

## المخرَج — درجة التعلّم (Learning Score)

بدل مقياس ضيّق «عدد نتائج البحث»، نقيس **ذكاء المنصّة** عبر القمع:

```
Search Success   نسبة عمليات البحث التي أعادت نتائج
View Rate        نسبة البحث → فتح نشاط
Contact Rate     → اتصال
Booking Rate     → حجز
Order Rate       → طلب/دفع
Review Rate      → تقييم
```

كل نسبة تُشتقّ من عدّادات مجهّلة (لا هوية مستخدم). ارتفاعها عبر الزمن = المنصّة تصبح أذكى. هذا هو **منحنى التعلّم**.

---

## لوحة «عقل AMANZINE» (Brain Dashboard)

ليست Dashboard إدارية — إنها **مرآة ذكاء النظام**. مصدر بياناتها `GET /api/knowledge/brain` (أدمن)، ويجمع ما نملكه اليوم:

- درجة التعلّم (القمع أعلاه).
- نسبة نجاح البحث (`search_daily`).
- أكثر الكلمات التي لا يفهمها النظام (`search_misses` — القانون ٥).
- *(لاحقًا)* أكثر الفئات/المدن طلبًا · Confidence حسب الفئة · نموّ المعرفة · دقّة النيّة/القرار.

> تُبنى واجهة اللوحة **بعد** أن تمتلئ الإشارات — لا لوحة فارغة.

---

## حدود الخصوصية (حاسمة)

- كل إشارات هذه الحلقة اليوم **مجمّعة ومجهّلة** (عدّادات يومية بلا `userId`).
- **قصّة المستخدم الكاملة** (ربط بحث→حجز→عودة لشخص بعينه) = `intent_history`، وهي **PII موقوفة على بوابة خصوصية** (`DR-0003` §7): موافقة صريحة + مدّة احتفاظ + عزل مستأجرين. لا تُبنى قبل قرار صريح.

---

## الحالة الحالية مقابل الهدف (Honesty Gap)

- ✅ موجود: Event Bus + Activity، `search_daily` (نجاح البحث)، `search_misses`، والمشترك `learning.js` + `learning_daily` (عدّادات القمع) + `/api/knowledge/brain`.
- 🟡 مشروط بالتغطية: بعض أحداث القمع (contact/review) تُحتسب فور ربط إصدارها في المسارات — المشترك جاهز لها.
- ⬜ لاحقًا: Confidence حسب الفئة، دقّة النيّة/القرار، نموّ المعرفة، وربط القصّة الكاملة (خلف بوابة الخصوصية).

---

## القاعدة العملية (لأي مطوّر، وأي AI)

> قبل أي إضافة، اسأل: **ما المعرفة التي تولّدها؟ وكيف تُحسّن القرار القادم؟** إن لم تفعل أيًّا منهما — أجّلها.

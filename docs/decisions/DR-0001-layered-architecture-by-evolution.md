# DR-0001: اعتماد نموذج الطبقات بالتطوّر لا بالهدم

- **التاريخ:** 2026-07-10
- **الحالة:** معتمَد
- **يمسّ:** المعمار · الدستور (القانون ٣، ٤، ٨)

## السياق
اقتُرحت خطة تنفيذ (Phase 2 Execution Plan) تعيد تنظيم AMANZINE حول الفلسفة الصحيحة:

```
Intent → Knowledge → Decision → Execution → Presentation
```

لكن الخطة تطلب **إنشاء عشرات المجلّدات والملفّات دفعة واحدة** (`core/ intent/ decision/ execution/ search/ analytics/ …` وما يزيد على ~٦٠ ملفًّا)، بمعظمها بلا منطق يسكنه بعد. هذا يصطدم مباشرةً بالقانون ٨ (تجميد المعمار) والقانون ٤ (لا محرّك/طبقة بلا مبرّر حقيقي).

## القرار
1. **نتبنّى نموذج الطبقات الخمس كـ "معمار مستهدف" رسمي** ومرجع للتفكير والتسمية.
2. **نصل إليه بالتطوّر التدريجي فوق الكود القائم**، لا بإعادة هيكلة كبرى. كل طبقة تُستخرَج **حين ينضج منطقها فعلًا**، خلف نفس العقود (القانون ٩).
3. **يُمنع** إنشاء ملفّات/مجلّدات هيكلية فارغة قبل وجود منطق يبرّرها اليوم.
4. الفصل المفاهيمي `Intent → Decision → Execution` **مُلزِم الآن** حتى لو عاشت الطبقات في ملفّات مشتركة مؤقّتًا (`search.js` يضمّ Decision+Execution اليوم).

## البدائل المرفوضة
- **إعادة الهيكلة الكبرى فورًا (Big-bang):** مرفوضة — تنتج دَينًا (ملفّات فارغة، استيرادات ميتة، مخاطر تراجع) دون قيمة للمستخدم، وتخالف القانون ٨. الرؤية التي لا تُشحَن بلا قيمة.
- **تجاهل نموذج الطبقات:** مرفوض — نخسر بوصلة معمارية تحمي هوية المشروع على المدى الطويل.

## الأثر
- **العقود:** لا كسر. الطبقات تُستخرَج خلف نفس العقود في `07_API_CONTRACTS`.
- **المسموح بعده:** استخراج طبقة إلى ملفّها حين ينضج منطقها (بلا DR جديد ما دام لا يكسر عقدًا).
- **الممنوع بعده:** إنشاء دفعة ملفّات/مجلّدات هيكلية فارغة (يحتاج DR مستقلًّا يبرّر كلًّا منها).

## المتابعة
- أول تنفيذ فعليّ لطبقة `Knowledge`: بناء `search_misses` وحلقة التعلّم (`04_KNOWLEDGE_GRAPH` §8) — أرخص خطوة وأعلاها أثرًا. يُوثَّق عند البدء في DR مستقلّ إن لزم إنشاء جدول.
- ترقية `Intent` نحو عقد `intent/v1` الكامل تدريجيًا (`03_INTENT_SPEC` §9) دون كسر المستهلكين.
